# Planning sources

Identified through search summaries on 16 November 2026. The network policy of the authoring session blocked these sites, so **the pages themselves were not opened in that session**. Inspect each page before a compliance or attribution claim relies on it. The controls in this standard are our policy and are not attributed to these authors as requirements.

## Requirements

- Gojko Adzic, [Specification by Example](https://gojko.net/books/specification-by-example/). Deriving shared, concrete examples from requirements before implementation and using them as acceptance checks. Informs RQ02 and RQ03.
- Martin Fowler, [GivenWhenThen](https://martinfowler.com/bliki/GivenWhenThen.html). The state, action and outcome structure for an example. Informs RQ03.
- Alistair Mavin, [EARS: Easy Approach to Requirements Syntax](https://alistairmavin.com/ears/). Constrained sentence templates with trigger, precondition and response. Informs RQ03; the template set is not adopted verbatim.
- Birgitta Böckeler, published on martinfowler.com, [Understanding Spec-Driven-Development: Kiro, spec-kit, and Tessl](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html). A practitioner's comparison of specification-first tools and their open questions. Attribute to Böckeler, not Fowler. Informs the caution that a written specification does not by itself make an agent follow it.

## Architecture

- Simon Brown, [The C4 model for visualising software architecture](https://c4model.com/). Context, container, component and code levels with labeled elements and relationships. Informs AR01; the notation is a project choice.
- Michael Nygard, [Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions). The original short decision-record format with context, decision, status and consequences. Informs AR02.
- Martin Fowler, [MonolithFirst](https://martinfowler.com/bliki/MonolithFirst.html) and [BoundedContext](https://martinfowler.com/bliki/BoundedContext.html). Starting with one deployable unit and choosing boundaries around coherent models. Informs AR03; it is guidance, not a prohibition of services.
- Neal Ford, Rebecca Parsons and Patrick Kua, *Building Evolutionary Architectures* (O'Reilly). Architectural fitness functions as automated checks of structural characteristics. Informs AR04. The book was not read for this standard; only the published concept is used.
