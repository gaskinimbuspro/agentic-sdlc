# Relational schema design (PostgreSQL)

These controls are our policy, informed by the [schema design sources](sources.md#schema-design). They govern the data model and its DDL before implementation; [DB01–DB08](database.md) govern its operation. The Planner records the model in the [discovery questionnaire](../planning/discovery.md) stage 8; the Implementer builds exactly that model.

| ID | Required control | Reject, for example | Basis |
| --- | --- | --- | --- |
| DD01 | Use lowercase unquoted identifiers of at most 63 bytes, no type prefixes or reserved words, and one recorded convention for table number, foreign key columns and constraint and index names. | `CREATE TABLE "CustomerOrder"`; `tbl_user`; two naming styles for foreign keys. | PostgreSQL lexical rules; wiki "Don't Do This"; SQL Style Guide |
| DD02 | Every table has a primary key. | A join table with neither primary key nor unique constraint. | PostgreSQL constraints |
| DD03 | Integer surrogate keys are `bigint GENERATED ALWAYS AS IDENTITY`. UUID keys use the native `uuid` type with a recorded choice of version: time-ordered v7 for index locality, random v4 where the creation time must not leak. | `id serial`; `id varchar(36)`; a public token generated as UUID v7. | wiki "Don't Do This"; PostgreSQL 18 UUID functions; RFC 9562 |
| DD04 | Every natural key in the approved model has a `UNIQUE` constraint in addition to the surrogate key. Case-insensitive uniqueness uses a unique index on a normalised expression or a decided collation. | `UNIQUE (tenant_id, email)` on raw text when emails are case-insensitive. | PostgreSQL expression indexes |
| DD05 | Declare every relationship as a foreign key with matching types and a recorded `ON DELETE`: `CASCADE` only where the child cannot exist without the parent, `RESTRICT` or `NO ACTION` for independent entities, `SET NULL` only on optional references. Cover referencing columns with an index unless an exception is recorded. | An `_id` column with no `REFERENCES`; `order_items.product_id ... ON DELETE CASCADE`; a foreign key with no supporting index on a large child table. | PostgreSQL constraints |
| DD06 | No foreign key crosses a module or service ownership boundary. Cross-boundary links are identifiers resolved through the owner's interface. | `billing.invoices.customer_id REFERENCES crm.customers` across two modules. | Fowler IntegrationDatabase; Richardson database per service; [AR03](../planning/architecture.md) |
| DD07 | Columns are `NOT NULL` unless the model records what an absent value means. Domain rules become row-local, immutable `CHECK` constraints; cross-row rules use `UNIQUE`, `EXCLUDE`, foreign keys or a documented trigger. | A nullable `name` with no recorded meaning; `CHECK (balance >= (SELECT ...))`. | PostgreSQL constraints |
| DD08 | Use `text`, optionally with a `CHECK` or domain, instead of `char(n)` or an arbitrary `varchar(n)`. | `country_code char(2)`; `surname varchar(20)`. | wiki "Don't Do This" |
| DD09 | A closed, small and stable value set may be an enum or a `CHECK`. A set that users change, that carries attributes or that can lose values is a lookup table. Required reference data is created by versioned migrations. | An enum for a product category list that marketing edits; reference rows inserted by hand in production. | PostgreSQL enumerated types; Sadalage and Fowler |
| DD10 | Monetary amounts are `numeric(p,s)` with a currency column, or integer minor units by recorded decision, with the rounding rule recorded. | `price double precision`; `total money`; `numeric` with no scale for invoice totals. | PostgreSQL numeric types; wiki "Don't Do This" |
| DD11 | Instants are `timestamptz`. Future local-time events store local time and an IANA zone name. Range conditions are half-open; overlap rules use range types with exclusion constraints. | `created_at timestamp DEFAULT now()`; `timetz`; `BETWEEN` on timestamps. | wiki "Don't Do This"; PostgreSQL date/time types |
| DD12 | Record a history policy per entity: hard delete, soft delete with partial unique indexes and a default filter, or an append-only history table with its own key, actor, time and action. The policy must satisfy retention and erasure duties. | `is_deleted boolean` that blocks re-registration; an audit table keyed by the audited row so it holds one entry. | Ambler and Sadalage refactoring catalog; [DB01](database.md), [PV04](privacy.md) |
| DD13 | Record the tenancy model. With a shared schema, every tenant-owned table has a non-null tenant column that leads its keys and indexes, and child foreign keys include it. Where row level security enforces isolation, enable and force it on every tenant table, connect with a role that neither owns the tables nor bypasses policies, and test it. | A child row able to reference another tenant's parent; row level security enabled while the application connects as table owner. | PostgreSQL row security; AWS multi-tenant RLS article |
| DD14 | Use `jsonb`, not `json`, and only for data treated as one opaque unit, with a recorded reason and bounded shape. Values that are filtered, joined, constrained or referenced are relational columns. | `attributes jsonb` holding a `customer_id` used in joins; a GIN index on every JSON column. | PostgreSQL JSON types |
| DD15 | Do not use entity-attribute-value tables, polymorphic associations, lists inside a column, repeated numbered columns, cloned tables per period or tenant, table inheritance or rules. | `entity_attributes(entity_id, name, value)`; `commentable_type` plus `commentable_id`; `tags text` holding `a,b,c`; `orders_2026`. | Karwin, *SQL Antipatterns* (chapter titles); Kent 1983; wiki "Don't Do This" |
| DD16 | The logical model is in third normal form unless a denormalisation is recorded with its measured need and the mechanism that keeps copies consistent. | `orders.customer_email` copied with no rule for staying in step. | Codd 1970; Kent 1983 |
| DD17 | Each index traces to a recorded query or constraint. Composite order follows the predicates, equality columns first. Remove duplicate and unused indexes. | An index on every column; `(a)` beside a unique `(a, b)` without a reason. | Winand, Use The Index, Luke; PostgreSQL multicolumn indexes |
| DD18 | Concurrent business edits use an optimistic version column checked on update, or a documented lock or isolation level. User-facing lists use keyset pagination with a deterministic order and a matching index. Use `NOT EXISTS`, not `NOT IN` with a subquery. | Read-modify-write of a balance with no version or lock; `ORDER BY created_at OFFSET 10000`. | Fowler Optimistic Offline Lock; Winand; wiki "Don't Do This" |
| DD19 | Change the schema only through versioned migrations. Make breaking changes in expand, migrate and contract steps across releases. Set a lock timeout for DDL; build indexes concurrently on live tables; add foreign keys and checks as `NOT VALID` and validate separately; avoid table rewrites under an exclusive lock; run backfills in bounded, restartable batches outside the DDL transaction. | Renaming a column in the release that changes the code; `CREATE INDEX` on a large live table; one `UPDATE` of every row inside the migration. | Sadalage and Fowler; Sato Parallel Change; PostgreSQL ALTER TABLE and CREATE INDEX; GitLab migration guide |
| DD20 | Classify every column. Keep personal and sensitive columns to the minimum, separate them where practical with tighter grants, and give each an erasure path that works with the chosen foreign key and history policy. Store passwords only as adaptive salted hashes. | `users.password text`; a national identifier with no classification or erasure rule. | [PV01, PV04](privacy.md); [DB01](database.md) |

## Automation

`operations-standard schema-lint <migrations>` statically rejects the mechanically decidable part of DD01–DD03, DD05, DD08, DD10, DD11 and DD14 in `CREATE TABLE` statements. It is a minimum. For DD19 use a migration linter such as squawk, and for DD02, DD05, DD13 and DD17 use catalog checks against a migrated database; neither is integrated in this repository. Ownership, composition versus independence, enum versus lookup, denormalisation, index-to-query traceability and classification remain review items tied to the questionnaire.

## Known gaps in the reference schema

The [reference migrations](../../reference/migrations) predate this standard. The lint reports `customers.tenant_id` without a foreign key and `customer_audit.customer_id` without `ON DELETE` (DD05). Review also finds a case-sensitive unique email (DD04), an audit table keyed by customer so it can hold one row per customer (DD12), and no row level security (DD13). They are recorded, not fixed: changing them affects three language bindings and the acceptance suite.
