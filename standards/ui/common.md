# Common UI/UX rules

Applicable rules below are mandatory for adopting projects. The obligation/evidence choices are our policy; sources inform them and do not publish this exact recipe. The [workflow](delivery-workflow.md) assigns accountable owners and the [case matrix](test-case-matrix.md) guides verification.

| ID | Rule | Check and rejection example | Sources |
| --- | --- | --- | --- |
| U01 | Define actors, actual user goals, scope and accepted outcomes before designing implementation tasks. Record assumptions and necessary user research. | Planner/product review; reject a screen inventory without a mapped user goal. | [SUI01](sources.md#sui01), [SUI02](sources.md#sui02) |
| U02 | Define routes, entry/deep-link behavior, navigation, browser back/forward and a recoverable destination for actions. | Design graph plus browser cases; reject an unresolved button destination or an unreachable required screen. | [SUI02](sources.md#sui02), [SUI03](sources.md#sui03) |
| U03 | Design loading, empty, error, success, default, unauthorized and forbidden states where applicable. A not-applicable decision needs a reason and design acceptance. | State matrix and component/browser evidence; reject an unexplained missing state or a spinner with no failure recovery. | [SUI02](sources.md#sui02) |
| U04 | Record versioned visual assets, responsive layouts, typography, spacing/color tokens and reusable component variants. Brand/product choices belong to the project. | Design review and controlled visual comparisons; reject arbitrary unreviewed baseline regeneration or inconsistent component variants. | [SUI04](sources.md#sui04), [SUI10](sources.md#sui10) |
| U05 | Use semantic HTML, accessible names and operable controls. Bind custom widgets to documented keyboard/focus behavior. | Automated DOM checks plus keyboard/assistive-technology review; reject a clickable element with no corresponding keyboard operation. | [SUI06](sources.md#sui06), [SUI07](sources.md#sui07) |
| U06 | Apply the project's WCAG 2.2 AA scope, including focus visibility, reflow, contrast, input assistance and accessible authentication where relevant. | Criterion-level evaluation record with unresolved failures; reject a conformance claim based only on an automated scan. | [SUI05](sources.md#sui05), [SUI07](sources.md#sui07) |
| U07 | Give fields persistent labels and actionable errors; preserve safe input during correction. Specify submit, duplicate-click, cancellation and destructive-operation behavior. | Form/component and real-backend cases; reject a failed submission that silently loses input or creates duplicate effects. | [SUI02](sources.md#sui02), [SUI08](sources.md#sui08) |
| U08 | Bind requests and all documented HTTP outcomes to the accepted backend contract. Define behavior when a request ends without a response, including uncertain write outcomes and safe recovery. Explain failures without exposing internals. | Contract mappings and real API integration; reject an unmapped response, blind retry of an uncertain write, or misleading success feedback. | [SUI09](sources.md#sui09), [backend B04/B07](../backend/common.md) |
| U09 | Keep credentials/secrets out of bundles, URLs and telemetry. Record session storage/lifetime, logout/tenant changes, XSS and conditional CSRF protections. Server authorization remains authoritative. | Security/design review and browser/API negative cases; reject sensitive browser storage assumptions or hidden UI controls as authorization evidence. | [SUI11](sources.md#sui11) |
| U10 | Separate view, state/behavior and transport responsibilities. Model exclusive states without contradictory flags; avoid duplicated derived/server state. Select extra state libraries only for actual needs. | Architecture/component review; reject stale cross-tenant cache reuse or contradictory saving/success states. | [SUI12](sources.md#sui12) |
| U11 | Bind supported runtime/framework/tool versions, lock files, strict checking, linting and production build commands before coding. Document relevant framework/server/client boundaries. | Clean install/static/type/build CI; reject an incomplete profile, unpinned build environment or disabled check. | [SUI13](sources.md#sui13) |
| U12 | Define supported browser/device/accessibility environments, locale/time-zone/formatting behavior and layout under long content, zoom and narrow views. | Agreed browser matrix and human/device checks; reject unsupported behavior hidden by desktop-only screenshots. | [SUI05](sources.md#sui05), [SUI06](sources.md#sui06) |
| U13 | Record measurable loading, interaction, layout-stability and bundle/network budgets with environment and measurement method. | Reproducible budget checks and field telemetry when available; reject a laboratory score presented as real-user percentile evidence. | [SUI14](sources.md#sui14) |
| U14 | Use behavior-oriented tests, isolated state/data and bounded observable waits. Test doubles must declare their scope; critical owned journeys exercise real integration separately. | Test review and repeatable reports; reject fixed sleeps hiding races or a stubbed critical journey presented as end-to-end proof. | [SUI09](sources.md#sui09), [SUI15](sources.md#sui15) |
| U15 | Preserve actual commands, counts, failed/skipped/flaky results, candidate/base/artifact identities, redacted traces and independent findings. | Trusted CI/review collection; reject missing/zero/stale evidence or a worker's self-approved exception. | [backend testing/evidence](../backend/testing.md#evidence-and-failures) |
| U16 | Version accepted design/contracts and record justified changes before affected tasks. Keep one bounded implementation task per workspace/context and independent review. | Coordinator readiness and candidate-bound acceptance; reject an implementer silently changing the accepted journey to match its code. | [delivery workflow](delivery-workflow.md), [backend agent contract](../backend/agent-contract.md) |

Each adopting project's rule inventory must name applicability, accountable owner, blocking stage and actual check/review evidence. The design validator covers declared structure/references, not all U01–U16 behavior. Existing violations and accepted exceptions require explicit migration/expiry controls; neither makes new violations acceptable.
