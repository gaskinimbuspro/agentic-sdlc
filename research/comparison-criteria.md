# Karşılaştırma ölçütleri

BMad Method, AWS AI-DLC ve GitHub Spec Kit aşağıdaki sorularla değerlendirilecek. Her yanıt birincil kaynağa ve incelenen sürüme bağlanacak. Boşluklar başarılı özellik olarak puanlanmayacak.

| Alan | Sorular |
| --- | --- |
| Proje girdisi | Ayrı hazırlanmış proje dokümanını kabul ediyor mu? Eksik veya çelişkili gereksinimleri nasıl ele alıyor? |
| Gereksinimler | Ürün davranışı, kabul kriterleri ve güvenlik veya performans beklentileri nasıl ifade ediliyor? |
| Mimari ve UX | Servis sınırları, veri sahipliği, API sözleşmeleri, ekran akışları ve ortak kararlar nerede tutuluyor? |
| Dil profilleri | Python, .NET ve Go'ya özgü kurallar nasıl seçiliyor, uygulanıyor ve güncelleniyor? |
| Roller | Roller ile gerçekten başlatılan ajan oturumları nasıl ayrılıyor? Sorumluluk ve devir koşulları belli mi? |
| Repo hazırlama | GitHub sahibi, görünürlük, isimlendirme, repo stratejisi ve başlangıç dosyaları nasıl belirleniyor? Gerçek repo oluşturma desteği var mı? |
| Görev yönetimi | Görevler gereksinimlere ve kararlara bağlanıyor mu? GitHub'a aktarım yerleşik mi, ek entegrasyon mu? |
| Doğrulama | Local test, CI, inceleme, kabul, smoke ve yayın kontrollerinin sorumlulukları nasıl ayrılıyor? |
| Bağımsız değerlendirme | Ajanın kendi testlerinden ayrı kabul kanıtı nasıl elde ediliyor? |
| Durum ve devam | Kesinti, tekrar deneme ve bağlam değişimi nasıl yönetiliyor? Mükerrer issue veya repo nasıl önleniyor? |
| Yetkiler | Dosya, ağ, servis ve deployment yetkileri nasıl sınırlandırılıyor? |
| Bakım ve maliyet | Sürüm geçişi, projelerde standart sapması, insan müdahalesi, süre ve maliyet nasıl izleniyor? |

Bir özelliğin var olması, bu kullanım senaryosunda yeterli olduğunu göstermez. Belge incelemesi ile çalışan deneyin sonuçları ayrı kaydedilecek.
